# 폴더 넘버링 컨벤션

폴더 이름 앞에 번호를 붙여 정렬 순서를 직접 지정하는 규칙이다. 프로젝트를 가리지 않고 그대로 가져다 쓸 수 있게 작성했다. 사람과 AI 모두 이 문서를 기본 규칙으로 사용한다. 현재 요청의 명시적인 지시가 이 문서보다 우선한다.

---

## 1. 왜 번호를 붙이는가

파일 탐색기와 에디터는 폴더를 이름순으로만 정렬한다. 이름순은 **읽는 순서**와 다르다. 번호를 붙이면 정렬 순서를 만드는 사람이 직접 정할 수 있다.

| | 번호 없음 | 번호 있음 |
| --- | --- | --- |
| 정렬 결과 | Animations, Data, Prefabs, Scenes, Scripts | 00. Scenes, 01. Scripts, 02. Prefabs, 03. Sprites, 04. Animations |
| 읽히는 방식 | 알파벳 순, 의미 없음 | 중요한 것 · 자주 여는 것부터 |

번호가 주는 것은 세 가지다.

- **순서** — 자주 쓰는 것, 먼저 봐야 하는 것이 위로 온다.
- **고정 위치** — 폴더가 늘어도 기존 폴더의 위치가 흔들리지 않는다. 손이 위치를 기억한다.
- **분류** — 번호대(00번대 / 90번대 / 99번대)만 봐도 그 폴더의 성격을 안다.

---

## 2. 기본 형식

```
NN. Name
```

- `NN` — **두 자리 숫자**. 한 자리는 `0`을 채운다. (`01`, 아니고 `1`)
- `.` — 마침표 하나.
- ` ` — 공백 하나.
- `Name` — **PascalCase 영문**. 공백·한글·특수문자를 쓰지 않는다.

```
⭕ 00. Scenes        ⭕ 01. Scripts        ⭕ 09. NodeMap
❌ 0.Scenes          ❌ 1. scripts        ❌ 09 - Node Map
```

두 자리로 고정하는 이유는 폴더가 10개를 넘는 순간 `1. / 10. / 2.` 순으로 정렬이 깨지기 때문이다. 100개를 넘길 일이 없다면 세 자리는 쓰지 않는다.

---

## 3. 번호대 구획

번호는 **1씩 순서대로 쓰지 않는다**. 용도별로 구간을 나눠 쓴다.

| 번호대 | 용도 | 예시 |
| --- | --- | --- |
| **00 ~ 89** | 정식 컨텐츠. 실제 순서를 갖는 폴더 | `00. Scenes`, `01. Scripts`, `02. Prefabs` |
| **90 ~ 98** | 개발 전용. 최종 빌드에 나가지 않거나, 작업용으로만 쓰는 것 | `90. Debug`, `90. ArtShare` |
| **99** | 잡동사니. 정리되지 않았거나, 외부에서 들어온 것 | `99. Externals`, `99. Tests`, `99. Documents` |

핵심은 **90번대와 99번대를 항상 맨 아래로 밀어두는 것**이다. 정식 폴더가 아무리 늘어도 임시·외부 폴더는 항상 목록 끝에 있다. 눈이 위쪽만 훑으면 된다.

---

## 4. 번호를 붙이는 규칙

### 4.1 자주 쓰는 것이 앞

번호 순서는 알파벳도, 만든 순서도, 중요도 서열도 아니다. **여는 빈도**가 기준이다. 하루에 열 번 여는 폴더가 `00`, 한 달에 한 번 여는 폴더가 뒤로 간다.

### 4.2 흐름이 있으면 흐름대로

씬처럼 진행 순서가 있는 것은 빈도보다 흐름을 우선한다.

```
00. Scenes/
  01. TitleScene
  02. SummonScene
  03. MapScene
  04. StageScene
```

### 4.3 번호는 한 번 정하면 바꾸지 않는다

폴더가 새로 생겼다고 기존 번호를 다시 매기지 않는다. 재정렬은 손이 기억하는 위치를 전부 무효화하고, 버전 관리에서는 전 파일 경로 변경으로 잡힌다. **새 폴더는 남는 번호에 넣는다.**

번호가 중간에 비어 있어도 그대로 둔다. `03`이 없고 `02` 다음이 `04`인 것은 문제가 아니다. 삭제된 폴더의 흔적이자, 그 번호를 재사용하면 헷갈린다는 표시다.

### 4.4 번호는 중복되면 안 된다

같은 위치에 같은 번호가 둘 있으면 정렬 순서가 이름으로 결정되어 번호가 무의미해진다.

```
❌ 05. Boss
   05. NodeMap
```

예외는 `99`뿐이다. `99`는 순서가 없는 잡동사니 구간이므로 `99. Tests`, `99. Documents`가 함께 있어도 된다.

### 4.5 진짜로 순서를 바꿔야 한다면

폴더 성격 자체가 바뀌어 번호를 옮겨야 할 때는 **한 번에, 단독 커밋으로** 처리한다. 다른 작업과 섞지 않는다. (커밋 라벨은 `🧹[Chore]`)

---

## 5. 어디까지 번호를 붙이는가

**2단계까지만 붙인다.** 3단계부터는 이름만 쓴다.

```
01. Scripts/            ← 1단계, 번호
  00. Core/             ← 2단계, 번호
    Interfaces/         ← 3단계, 번호 없음
    Utilities/
  07. UI/
    MainMenuView.cs
```

깊은 곳까지 번호를 붙이면 관리 비용만 늘고 얻는 게 없다. 3단계 폴더는 보통 개수가 적고, 그 안에서는 이름순 정렬이면 충분하다.

**한 폴더 안에서는 전부 붙이거나 전부 안 붙인다.** 번호 있는 폴더와 없는 폴더가 섞이면 없는 쪽이 아래로 밀려 순서가 깨진다.

### 5.1 번호를 붙이지 않는 것

- **외부에서 받은 것** — 에셋 스토어, 패키지, 라이브러리. 받은 경로 그대로 둔다. 이름을 바꾸면 업데이트할 때 충돌하고, 내부 참조가 깨질 수 있다.
- **도구·엔진이 위치를 정하는 폴더** — 이름이나 경로가 고정된 특수 폴더. 번호를 붙이면 인식되지 않는다.
- **파일** — 파일 이름에는 번호를 쓰지 않는다. 단, 순서 자체가 의미인 경우(씬, 챕터, 단계별 문서)는 예외다.

## 6. 폴더가 스스로를 설명하게 한다

폴더마다 `README.txt`(또는 `README.md`)를 하나 둔다. 세 줄이면 충분하다.

```
UI 프리팹.
화면 단위 프리팹만 이 폴더에 두고, 부품 단위는 Components/ 아래에 둔다.
NodeMap 관련은 05. NodeMap 으로.
```

폴더 이름 하나로는 "여기에 무엇을 넣어야 하는가"가 전달되지 않는다. 특히 비어 있는 폴더, 이름이 비슷한 폴더 두 개가 있을 때 필요하다.

---

## 7. 새 프로젝트 시작 템플릿

프로젝트 성격에 따라 이름은 바뀌지만 구획은 그대로 쓴다.

```
00. Scenes        ← 진입점. 가장 자주 연다
01. Scripts       ← 가장 자주 고친다
02. Prefabs
03. Sprites
04. Animations
05. Arts          ← 폰트, 사운드, 셰이더
06. Data          ← 설정 에셋, 데이터 파일
07. Settings
...
90. ArtShare      ← 작업 원본 (.aseprite, .psd 등)
90. Debug         ← 개발 전용
99. Documents
99. Externals     ← 외부 반입물
99. Tests
```

시작할 때 `08`부터 `89`까지는 비워 둔다. 나중에 늘어날 자리다.

---

## 8. 체크리스트

폴더를 새로 만들 때 확인한다.

- [ ] `NN. Name` 형식인가 (두 자리 숫자 + 마침표 + 공백 + PascalCase)
- [ ] 같은 위치에 같은 번호가 이미 있지 않은가
- [ ] 정식 / 개발 전용(90) / 잡동사니(99) 중 맞는 번호대인가
- [ ] 기존 폴더 번호를 건드리지 않았는가
- [ ] 3단계 이하에 불필요하게 번호를 붙이지 않았는가
- [ ] 용도가 이름만으로 안 드러나면 README를 넣었는가
