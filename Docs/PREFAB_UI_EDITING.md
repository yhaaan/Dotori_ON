# Unity에서 DOTORI ON UI 조정하기

이제 화면은 런타임 코드로 생성되지 않고 아래 네 개의 실제 프리팹을 사용합니다.

- `Assets/02. Prefabs/DOTORIONCanvas.prefab`: 메인 화면 전체
- `Assets/02. Prefabs/TeamMemberCard.prefab`: 메인 화면에 중첩된 멤버 카드 원본
- `Assets/02. Prefabs/FirstRunNameModal.prefab`: 최초 실행 이름 설정 화면
- `Assets/Resources/DOTORION/DOTORIONApp.prefab`: 앱 시작점과 위 프리팹 참조

## 권장 편집 순서

1. Unity Project 창에서 `DOTORIONCanvas.prefab`을 더블 클릭합니다.
2. Prefab Mode에서 위치, 크기, 색상, 글자 크기와 버튼 모양을 조정합니다.
3. 네 카드에 공통으로 적용할 디자인은 `TeamMemberCard.prefab`에서 수정합니다.
4. 최초 이름 입력 화면은 `FirstRunNameModal.prefab`에서 수정합니다.
5. Play 버튼으로 480x220 화면과 버튼 동작을 확인합니다.
6. `DOTORI ON > Build Windows x86_64`로 빌드합니다.

`DOTORI ON > Create Missing Editable UI Prefabs`는 파일이 없을 때만 생성하며 기존 수정 내용을 덮어쓰지 않습니다.

**프리팹을 다시 만드는 메뉴는 없습니다.** 프리팹에는 이제 다른 어디에도 없는 아트가 들어 있어서, 재생성은 스프라이트·9-slice·손으로 맞춘 rect를 전부 지웁니다. `DOTORIONPrefabBuilder.RebuildPrefabsFromCommandLine`과 `RebuildCardAndMainView`는 코드로 남아 있으니, 정말 초기화가 필요하면 스크립트에서 이름으로 부르세요. 메뉴에서 실수로 눌릴 일은 없습니다.

`DOTORI ON > Apply Avatar Icon Layout`은 아직 메뉴에 있고 카드의 아바타·이름·상태·상세 줄 rect를 덮어씁니다. 카드 레이아웃을 손으로 맞춰 뒀다면 누르지 마세요.

## 폰트

**TextMeshPro는 쓰지 않습니다.** 프리팹의 텍스트 235개가 전부 레거시 uGUI `Text`이고, 코드에도 `TMPro` 참조가 없습니다. 그래서 폰트를 **굽지 않고** `.ttf`를 Font 슬롯에 그대로 꽂습니다. TMP로 가려면 컴포넌트를 전부 `TextMeshProUGUI`로 갈아야 하므로, 그 작업을 할 이유가 생기기 전까지는 이 구조가 더 싸게 먹힙니다.

폰트는 `Assets/DungGeunMo.ttf`이고 빌더의 `PreviewFont()`도 같은 파일을 씁니다. 파일이 없으면 Unity 내장 폰트로 떨어지므로, 폰트를 잃은 체크아웃에서도 프리팹이 빈 글자로 만들어지지는 않습니다.

**프리팹에 넣은 폰트가 그대로 실행됩니다.** 예전에는 `UiFactory.ApplyApplicationFont`가 `Initialize`에서 화면 안의 모든 `Text`를 훑어 OS 폰트(맑은 고딕)로 덮어썼습니다. UI를 런타임에 만들던 시절, 내장 Arial에 한글 글리프가 없어서 필요했던 장치입니다. 프리팹이 한글 폰트를 직접 들고 있는 지금은 아트를 지우기만 해서 걷어냈습니다. **프리팹에서 폰트를 바꿨는데 실행하면 돌아온다면 이런 종류의 코드가 다시 생긴 것입니다.**

**임포터의 Rendering Mode는 `Hinted Raster`여야 합니다.** 기본값 `Smooth`는 안티에일리어싱을 걸어서 픽셀 폰트를 흐리게 만듭니다. Character는 `Dynamic`으로 둡니다 — 한글은 글리프가 너무 많아 미리 구울 수 없습니다.

**글자 크기는 아직 폰트의 격자와 맞지 않습니다.** 둥근모는 16px 그리드에서 그려졌는데 UI가 쓰는 크기는 9·10·11·12입니다. 16px 글리프를 줄여 쓰는 셈이라 가장자리가 뭉갭니다. 크기를 16으로 올리면 또렷해지지만 줄 높이를 다시 잡아야 하고, 특히 카드의 `Detail`은 27px 안에 두 줄을 넣는 자리라 들어가지 않습니다. 지금은 뭉개짐을 받아들이고 크기는 화면을 보면서 정하기로 했습니다.

## 색은 누가 정하는가

**패널과 버튼의 기본 색은 프리팹이 정합니다.** 코드는 더 이상 배경을 칠하지 않습니다 — 카드 배경, 상단바 `설정`·`통계`·`출석` 버튼, 하단 컨트롤 바의 `출근`·`퇴근`·`작업중`·`쉬는중`·`식사중`, 통계 패널의 탭·기간·지표 버튼, 설정 패널 토글, 대시보드 행, 랭킹 행이 전부 그렇습니다. 아직 아트가 없는 아바타 선택창만 예외입니다. 프리팹에 넣은 스프라이트와 색이 그대로 화면에 나옵니다.

**코드가 여전히 칠하는 것은 뜻이 있는 색뿐입니다.**

| 남아 있는 색칠 | 어디 |
| --- | --- |
| 상태색(작업중·쉬는중·식사중·오프라인) | 카드 아바타 타일과 상태 글자, 소형 모드 pill |
| 메모 알림 점멸 | 소형 모드 점 |
| 달력 히트맵 | 통계 패널 달력 칸 |
| 랭킹 지표색 | 랭킹 막대와 라벨 |
| 오류/보통 피드백 글자 | 각 화면 하단 줄 |

그래서 **상태색이 곱해지는 자리의 아트는 흰색 계열로 그려야 합니다.** 아바타 타일에 이미 색이 들어 있으면 상태색과 곱해져 탁해집니다.

**하단 컨트롤 바는 지금 어느 버튼이 눌린 상태인지 색으로 말하지 않습니다.** 예전에는 고른 상태의 버튼만 상태색으로 칠했지만, 아트가 들어오면서 그 칠이 그림을 덮었습니다. 지금 내 상태를 말해 주는 것은 내 카드의 상태 글자와 아바타 타일이고, 버튼 쪽 표시가 필요하면 눌린 상태용 스프라이트를 따로 두는 편이 맞습니다.

**아트가 들어간 버튼의 hover는 회색조로 살짝 어두워집니다.** 상단바 7개, 하단 컨트롤 바 5개, 카드의 `Nudge`가 `Highlighted` 0.85, `Pressed` 0.7입니다. 예전에는 `Highlighted`가 남색(`#34445D`)이라 hover가 색을 입혔지만, 회색조는 명도만 낮춰서 그림의 색이 그대로 남습니다.

**요청이 오가는 동안에도 아트가 그대로 있습니다.** `DOTORIONView.SetBusy`가 버튼 10개를 `interactable = false`로 만드는데, 예전에는 Button의 `Disabled` 색(`0.48, 0.52, 0.58`, 알파 0.55)이 곱해져 누르지 않은 버튼들까지 한순간 어두워졌습니다. 아트가 들어간 13개는 `Disabled`를 흰색 불투명으로 두어 눈에 아무 변화가 없습니다. **막히는 것은 클릭이지 그림이 아닙니다.**

ColorTint는 **곱하기**라 흰색보다 밝게는 못 만듭니다. hover에서 밝아지게 하려면 `Normal`을 0.88쯤으로 낮춰 평소를 어둡게 깔아야 하고, 그만큼 그림이 원본보다 어둡게 나옵니다. 그래서 밝히는 대신 어둡게 하는 쪽을 골랐습니다.

## 주의할 참조

각 프리팹 루트 컴포넌트의 `Prefab references` 필드는 버튼 동작과 데이터 바인딩에 사용됩니다. 계층 안의 오브젝트를 삭제하거나 교체했다면 대응하는 필드를 새 오브젝트로 다시 연결하세요. 단순한 위치, 크기, 색상, 텍스트 스타일 수정에는 참조를 바꿀 필요가 없습니다.

메인 화면 우측 상단은 `전체호출` · `소형` · `통계` · `설정` · `—` · `×`로 빈틈 없이 채워져 있고, `출석` 버튼과 누적 포인트는 왼쪽 드래그 영역 안, 버전 표시 오른쪽에 있습니다. `—`는 작업 표시줄로 최소화하고, `×`는 퇴근 처리를 시도한 뒤 앱을 완전히 종료합니다. Alt+F4도 `×`와 같은 경로로 갑니다.

시스템 트레이로 숨기는 `숨김` 버튼은 제거했습니다. 트레이 아이콘이 Windows 11의 오버플로 영역에 가려지면 창을 되찾을 방법이 없고, `forceSingleInstance` 때문에 재실행까지 막혀 작업 관리자로 프로세스를 죽여야 했습니다. 최소화는 항상 작업 표시줄에 남으므로 같은 용도를 안전하게 대신합니다.

## 상태 메모 입력칸

하단 컨트롤 바 오른쪽의 `StatusNoteInput`(`DOTORIONView._statusNoteInput`)은 지금 뭘 하는지 24자까지 적는 칸입니다. 출근 중일 때만 보이고, Enter를 누르거나 포커스를 잃으면 저장됩니다. 서버가 퇴근 시 자동으로 비웁니다.

글자 수 제한을 늘리려면 InputField의 `Character Limit`만이 아니라 `member_current_state.status_note`의 CHECK 제약도 같이 고쳐야 합니다. 카드 폭이 약 110px라 그 이상은 어차피 잘립니다.

## 소형 모드

상단 바의 `소형`(`TopBar/MiniMode`, `DOTORIONView._miniModeButton`)을 누르면 창이 130x150으로 줄고 반투명해집니다. 이름과 상태만 네 줄로 보이며, **창 아무 곳이나 더블클릭하면** 원래 크기로 돌아옵니다. 맨 위 18px 띠(`MiniOverlayPanel/MiniDragStrip`)만 창을 끄는 손잡이입니다. 본문이 드래그까지 맡으면 네이티브 창 이동 루프가 마우스를 눌리는 순간 가져가 버려서, 더블클릭의 첫 번째 클릭이 사라집니다.

`MiniOverlayPanel`은 `WindowBackground`의 자식이 아니라 형제이고, 아바타 선택창과 달리 펼쳐지는 게 아니라 **`WindowBackground`를 통째로 끄고 대신 켜집니다.**

패널 크기(130x150)는 `WindowsOverlayWindow.MiniWindowWidth`·`MiniWindowHeight`와 같아야 하며 `PrefabAssetTests`가 함께 고정합니다. 행 안의 그래픽은 전부 `Raycast Target`이 꺼져 있어야 합니다. 켜져 있으면 그 자리가 더블클릭을 먹어서 창을 되돌릴 수 없는 죽은 영역이 됩니다. 이것도 테스트가 잡습니다.

소형 모드에서는 캔버스 스케일러가 `Constant Pixel Size`로 바뀝니다. 평소 설정(`Scale With Screen Size`, 기준 480 폭)을 그대로 두면 창 폭이 130이 될 때 UI 전체가 0.27배로 줄어들어 글씨가 사라집니다. 그래서 소형 패널만 캔버스 기준 좌표가 아니라 **실제 픽셀 값으로** 만듭니다. 원래 설정은 `DOTORIONView.Initialize`가 프리팹에서 읽어 두었다가 복귀할 때 되돌리므로, 스케일러를 손봐도 소형 모드를 다녀오면서 값이 굳지 않습니다.

반투명은 `WS_EX_LAYERED` + `SetLayeredWindowAttributes`로 창 전체에 균일하게 겁니다(`MiniWindowAlpha = 225`). 글자까지 같이 비치는 방식이며, 배경만 투명하게 하려면 프레임버퍼 알파가 필요해서 URP 쪽 작업이 따로 붙습니다. **레이어드 창은 DXGI 플립 모델과 같이 못 쓰기 때문에 Player Settings의 `Use DXGI Flip Model Swapchain`이 꺼져 있어야 합니다.** 다시 켜면 반투명이 조용히 사라집니다.

소형 모드를 오갈 때는 `DOTORIONView`가 몇 프레임에 걸쳐 모든 `Text`의 정점 캐시를 버립니다. 동적 폰트 아틀라스는 새 크기의 글리프를 요청받으면 다시 패킹되면서 이미 들어 있던 글리프 위치를 전부 바꾸는데, uGUI는 내용이 그대로면 예전 정점을 재사용하기 때문에 UV가 옛 자리를 가리켜 **텍스트만** 뭉개집니다. 실제로 그렇게 한 번 깨졌습니다. 이 무효화를 지우면 다시 재현됩니다.

Windows는 시스템 최소 창 폭(보통 130~140px) 아래로는 창을 줄여 주지 않습니다. `WindowsOverlayWindow`가 `WM_GETMINMAXINFO`에서 그 하한을 낮추기 때문에 130이 통과합니다.

마지막 상태는 `PlayerPrefs`의 `DOTORION.MiniMode`에 남아 다음 실행 때 그대로 켜집니다. 대시보드의 `다른 이름으로 로그인`으로 이름 화면에 돌아갈 때는 창만 원래 크기로 되돌리고 이 값은 건드리지 않으므로, 다시 로그인하면 남겨 둔 대로 뜹니다.

에디터 Play 모드에서는 창 조작이 전부 no-op이라 패널만 좌상단에 130x150으로 그려집니다. 크기와 반투명은 빌드에서만 확인할 수 있습니다.

## 메모 알림

팀원이 상태 메모를 남기면 두 가지가 일어납니다.

- **작업 표시줄이 깜박입니다** — 창이 포커스를 잃었거나, 소형 모드거나, 대시보드가 열려 있을 때만
- **소형 모드에서 그 사람의 상태 점이 붉게 점멸합니다**

**전체 화면을 보고 있으면 둘 다 일어나지 않습니다.** 메모가 이미 카드에 적혀 있으니 알릴 이유가 없습니다. 반대로 전체 화면으로 돌아오는 순간 쌓여 있던 알림이 한 번에 사라집니다 — 메모들은 같은 화면의 카드에 다 있어서, 한 명씩 확인시키면 이미 본 것이 계속 깜박이게 됩니다.

이벤트는 폴링된 스냅샷을 비교해서 만듭니다(`MemberStatusNoteChanged`). 요청이 늘지 않고, 메모를 지우는 것은 알리지 않습니다. 서버가 퇴근 시 자동으로 비우는 것도 마찬가지입니다.

같은 사람이 메모를 고쳐 써도 **작업 표시줄은 한 번만** 깜박입니다. 아직 안 읽은 메모를 다시 쓴 것이라 두 번 부를 일이 아닙니다. 아무도 안 본 사이에 메모를 지우면 점멸도 멈춥니다(`UnreadNoteTracker.RetainOnly`).

점멸 주기는 `MiniMemberRowView.BlinkSeconds`(0.9초)입니다. 점 색은 `Bind`가 아니라 `Update`에서 칠합니다 — `Bind`는 초당 다섯 번이라 매끄럽지도 고르지도 않습니다.

## 자리비움 자동 감지

출근 중에 데스크톱 입력이 **10분** 없으면 상태가 자동으로 `쉬는중`이 되고, 다시 입력이 들어오면 `작업중`으로 돌아옵니다. 유휴 시간은 `GetLastInputInfo`로 읽으며, 이 값은 이 프로세스가 아니라 **세션 전체**의 마지막 입력이라 다른 프로그램을 쓰고 있어도 자리에 있는 것으로 잡힙니다.

**되돌리는 것은 이 기능이 만든 `쉬는중`뿐입니다.** `식사중`이거나 직접 눌러서 고른 `쉬는중`은 본인이 자기 상태를 말한 것이라, 키보드를 건드렸다는 이유로 뒤집지 않습니다. 판단 규칙은 `IdleActivityPolicy`에 따로 있고 `IdleActivityPolicyTests`가 이 경계들을 고정합니다.

상태 변경 요청이 실패하면 그 부재 동안은 다시 시도하지 않습니다. 몇 초마다 같은 오류를 반복하는 것보다, 이 기능이 없던 때와 같은 동작(작업중 유지)으로 남고 다음 부재에 다시 시도하는 편이 낫습니다.

임계값을 바꾸려면 `DOTORIONApp.IdleBreakSeconds`를 고칩니다. 짧게 잡을수록 통계는 정확해지지만 화장실 다녀오는 사이에 상태가 바뀌는 게 감시처럼 느껴질 수 있습니다.

에디터 Play 모드에서는 유휴 시간이 항상 0으로 보고됩니다. 입력을 물어볼 수 없는 곳이 "아무도 안 앉아 있다"로 읽히면 안 되기 때문입니다.

## 절전과 종료

| 상황 | 처리 | 퇴근 사유 |
| --- | --- | --- |
| `×` 버튼 · Alt+F4 | 퇴근 시도 후 종료 | `manual` |
| Windows 종료·로그오프 | 셸이 기다려 주는 동안 퇴근 | `os_shutdown` |
| 절전 진입 | 약 2초 안에 최선 노력 퇴근, 앱은 계속 실행 | `os_shutdown` |
| 앱이 죽거나 네트워크 단절 | 서버가 3분 뒤 정리 | `auto_timeout` |

절전 처리는 **기록의 정확도를 위한 게 아닙니다.** 서버의 `close_stale_attendance_sessions`가 이미 마지막 heartbeat 시각으로 되돌려 세션과 활동 구간을 닫기 때문에, 처리하지 않아도 시각 오차는 heartbeat 주기인 45초 수준입니다. 이 기능이 사는 건 **팀원 목록**입니다. 없으면 노트북을 덮은 사람이 최대 3분간 자리에 있는 것처럼 보입니다.

절전은 종료와 달리 아무도 기다려 주지 않습니다. `WM_QUERYENDSESSION`에는 `ShutdownBlockReasonCreate`로 시간을 벌 수 있지만 `PBT_APMSUSPEND`에는 그런 수단이 없어서, 요청이 못 닿으면 그대로 두고 서버 정리에 맡깁니다.

## 퇴근 요약

퇴근이 성공하면 피드백 줄이 `퇴근했습니다` 대신 오늘의 근무·작업 시간으로 바뀝니다. 휴식과 식사는 0이 아닐 때만 붙습니다 — 줄 폭이 좁고, `00:00`은 읽는 사람이 이미 아는 것을 말할 뿐입니다.

통계 패널이 쓰는 값을 그대로 씁니다. 퇴근이 반영되고 명단을 다시 받은 뒤에 요청하므로 방금 닫힌 세션이 포함됩니다. Mock 백엔드처럼 기록이 없는 곳에서는 조용히 기존 메시지가 남습니다.

## 출석체크

상단바 왼쪽, 버전 표시 오른쪽의 `출석` 버튼입니다. 하루 한 번 10포인트를 받고, 옆에 누적 포인트가 붙습니다. 포인트를 쓸 곳은 아직 없습니다.

**하루 한 번은 서버가 보장합니다.** `member_check_ins`의 기본키가 `(member_id, local_date)`라 두 번째 삽입이 물리적으로 불가능합니다. 클라이언트가 판단하면 앱을 껐다 켜서 무한히 받을 수 있습니다.

날짜는 팀 로컬(Asia/Seoul)이고 **하루는 자정이 아니라 오전 6시에 바뀝니다.** 새벽 3시에 누르면 전날 출석으로 잡힙니다.

밤을 넘겨 일하는 일이 잦아서 자정 경계가 한 자리를 이틀로 쪼개고 있었습니다. 22시~2시 세션이 반나절 두 개가 되고, 새벽 1시 출석이 아직 시작하지도 않은 날로 계산됐습니다. 게임들이 오래 써 온 기준이기도 하고, 그 시각엔 경계에 놀랄 사람이 없습니다.

기준은 서버의 `team_day_offset()` 한 곳에 있고, 클라이언트의 `TeamDay.StartHour`가 그 값과 맞아야 합니다. `TeamDayTests`가 그 일치를 고정합니다. 자정과 6시 사이에 클라이언트만 옛 기준을 쓰면, 서버가 어제로 기록한 것을 오늘에서 찾게 되어 퇴근 요약이 비고 달력이 엉뚱한 달을 요청합니다.

**통계와 달력도 같은 경계를 씁니다.** 안 그러면 "출석은 어제, 통계는 오늘"로 갈라집니다. 저장된 세션 시각은 그대로이고 묶는 방식만 바뀌므로, 경계를 다시 옮기려면 `team_day_offset()`과 `TeamDay.StartHour`만 고치면 됩니다.

UTC 기준으로 두지 않은 이유는 따로 있습니다. 그랬다면 한국 오전 9시에 날짜가 넘어가서, 근무 중에 거부하다가 점심 전에 두 번째를 내줬을 겁니다.

포인트는 행마다 저장합니다. 나중에 하루 가치를 바꿔도 지난 기록이 소급되지 않습니다.

**버튼은 드래그 영역 안, 버전 표시 오른쪽(126~206)에 있습니다.** 상단바 오른쪽은 통계·소형·전체호출로 빈틈이 없어서 거기 놓으면 다른 버튼 뒤에 깔립니다(실제로 한 번 그랬습니다). Button이 자기 pointer-down을 소비하므로 드래그 영역 안에 있어도 창 드래그를 방해하지 않습니다.

## 연속 출석

`daily_check_in_streak`이 **오늘 또는 어제로 끝나는** 연속 일수를 셉니다. 어제까지 인정하는 이유는 아침에 버튼을 누르기 전마다 0으로 보이면 안 되기 때문이고, 이틀 전에 끊긴 기록을 이어진 것처럼 보이게 하는 것은 연속 표시가 절대 하면 안 되는 일이라 거기서 끊습니다.

출석을 누르면 피드백에 연속 일수가 함께 뜨고, **랭킹 탭에서는 이름 아래에 누적 포인트와 연속 일수**가 보입니다. 두 값은 랭킹 기간에 속하지 않고 사람에게 속하므로 기간(7일·이번 달·누적)을 바꿔도 그대로입니다.

받은 뒤에도 버튼과 누적 포인트는 남습니다. 사라지면 포인트를 잃은 것처럼 읽힙니다. 통계처럼 선택 기능이라 지원하지 않는 백엔드에서는 버튼이 아예 숨습니다.

## 이름 변경과 계정

이름이 곧 계정입니다. Auth 이메일과 비밀번호가 **둘 다 이름에서 유도**되므로(`DerivedTeamCredentials`), 이름을 바꾸면 자격증명 자체가 바뀝니다.

| 하는 일 | 어디서 | 결과 |
| --- | --- | --- |
| 최초 실행에 이름 입력 | 이름 화면 | 있으면 **로그인**, 없으면 새 계정 |
| 자기 이름 더블클릭 | 카드 | **제자리 이름 변경**, 기록 유지 |
| 남의 이름으로 변경 시도 | 카드 | **거부**(`member_name_taken`) |

자기 카드의 이름에 붙은 `DoubleClickHandle`(`TeamMemberCardView._nameDoubleClick`)이 입구입니다. 본인 카드에서만 켜지며, 출근 중이든 아니든 됩니다 — 세션은 건드리지 않습니다.

**새 PC에서 자기 이름을 넣는 것은 평범한 로그인입니다.** 기록이 그대로 이어집니다. 거부되는 건 이미 로그인한 상태에서 남의 이름으로 바꾸려 할 때뿐입니다.

`rename_member`는 members 행과 Auth 계정(이메일·비밀번호·identities)을 **한 트랜잭션에서** 바꿉니다. 반쯤 적용된 상태 — 이름과 자격증명이 어긋난 계정 — 는 아무도 로그인할 수 없어서 복구가 불가능하기 때문입니다.

자격증명은 클라이언트가 만들어 보냅니다. 다음 실행에서 그 값을 재현해야 하는 쪽이 클라이언트라, 서버가 따로 유도하면 어긋날 길만 생깁니다. 파생식이 빌드에 들어 있어 값을 넘긴다고 새로 드러나는 비밀도 없습니다.

Windows 자격 증명 관리자에 이름별로 저장되는 세션(`ProjectDDD.DOTORION.SupabaseAuth.<project-ref>.<이름 키>`)은 로그인 왕복을 한 번 아끼는 캐시일 뿐입니다. 이름을 바꾸면 새 키로 찾게 되어 캐시가 없으니 한 번 더 로그인할 뿐, 지워져도 이름만 다시 입력하면 복구됩니다.

**이는 보안 경계가 아닙니다.** 앱을 가진 사람은 누구든 팀원 이름으로 접속할 수 있으며, 4인 내부 도구라는 전제에서 내린 선택입니다.

서버가 성공한 뒤 로컬 프로필 기록이 실패하면 다음 실행에서 로그인이 막힙니다. 그때는 이름 화면에 **새 이름**을 입력하면 스스로 회복됩니다.

## 개발자 대시보드

`Ctrl+Shift+D`로 열고 닫습니다. 새 Input System만 켜져 있어 `Keyboard.current`로 읽습니다.

멤버 명단과 세션 수·누적 시간·포인트·마지막 퇴근을 보여주고, 아래 두 가지를 할 수 있습니다.

**멤버 삭제** — 계정과 모든 기록을 지우고 팀 자리를 반환합니다. 되돌리기가 없어서 이름을 되읽어 주는 확인을 거칩니다. 자기 행에는 버튼이 없습니다(서버가 거부하므로 눌리게 두면 손쓸 수 없는 오류만 납니다).

`attendance_sessions`·`activity_intervals`·`team_events`는 `on delete restrict`로 묶여 있어 원래 지워지지 않습니다. 실수로 근무 기록이 날아가는 걸 막는 장치라 제약을 푸는 대신 `admin_delete_member` 안에서만 의존 순서대로 비웁니다.

**다른 이름으로 로그인** — 이 PC의 로컬 프로필만 지우고 이름 화면으로 돌아갑니다. 서버는 건드리지 않아서 같은 이름을 다시 넣으면 그대로 이어집니다. **로그아웃 전에 퇴근 처리를 먼저 합니다** — 세션이 이 설치의 client instance id로 열려 있어서, 새로 로그인하면 서버가 그 세션의 heartbeat과 퇴근을 거절합니다.

대시보드는 창 크기를 300px 늘립니다. 통계 패널·아바타 선택창·소형 모드도 각자 창을 움직이므로 대시보드를 열 때 전부 닫힙니다.

### 권한

`members.is_admin`으로 막게 되어 있지만 **지금은 개발 중이라 활성 멤버 전원에게 열려 있습니다**(`202608280006_open_admin_for_development.sql`). 정식 운영 전에 `is_team_admin()`을 원래 조회로 되돌리고 콘솔에서 한 번 지정하면 됩니다:

```sql
update public.members set is_admin = true where display_name = '이름';
```

모든 관리자 함수가 `is_team_admin()` 하나만 물어보므로 그 함수만 고치면 끝납니다.

**이건 보안 경계가 아닙니다.** 이름이 곧 자격증명이고 파생식이 빌드 안에 있어서, 관리자 이름을 아는 사람은 그 계정으로 들어올 수 있습니다. 막는 것은 팀원이 실수로 파괴적인 화면에 들어가는 것이고, 그건 실제로 일어나는 일입니다.

## 설정 패널

`설정` 버튼(예전 `TOP` 자리)을 누르면 `SettingsPanel`이 열리고 창이 패널 높이(160px)만큼 아래로 늘어납니다. 통계 패널과 같은 방식이라 패널 높이와 `WindowsOverlayWindow.SettingsPanelHeight`는 같은 값이어야 하고, `PrefabAssetTests`가 두 값을 함께 고정합니다. 창을 직접 움직이는 다른 패널(통계·아바타·대시보드·소형 모드)과는 동시에 열리지 않습니다.

| 줄 | 하는 일 | 남는 곳 |
| --- | --- | --- |
| `항상 위` | 다른 창 위에 계속 띄웁니다 | 창 스타일. 저장하지 않습니다 |
| `알림음` | 출근·퇴근·호출 소리를 끕니다 | `PlayerPrefs`의 `DOTORION.Muted` |
| `버전` | 실행 중인 빌드의 `Application.version` | — |

**`항상 위`는 예전 `TOP` 버튼 그대로입니다.** 상단바 480px에 버튼이 더 들어갈 자리가 없어서, 한 자리로 전부를 여는 쪽으로 바꿨습니다. 창 스타일이라 다음 실행에는 켜진 상태로 시작합니다(`DOTORIONApp.Awake`가 `SetAlwaysOnTop(true)`).

**`알림음`은 음소거이지 볼륨 0이 아닙니다.** `DOTORIONSounds`의 볼륨 설정이 그대로 살아 있어야 다시 켰을 때 원래 크기로 돌아옵니다. 스위치 표시는 "소리가 켜져 있는가"로 읽습니다 — 음소거일 때 켜진 색이면 방금 한 일과 반대로 읽힙니다.

**끄는 것은 내가 듣는 소리뿐입니다.** 소리는 전부 받는 쪽에서 납니다 — 내 출근은 내 PC에서 울리지 않고(`!isLocalActor`), 남에게 무엇을 보내지도 않습니다. 그래서 이 스위치는 "남의 출근·퇴근·호출을 내가 안 듣는다"이고, 내가 조용히 출근하는 기능이 아닙니다.

계정 삭제는 두지 않았습니다. 되돌릴 수 없는 일을 팀원이 매일 여는 패널에 두는 것보다, 대시보드(`Ctrl+Shift+D`)에서 관리자가 지우거나 SQL 콘솔에서 처리하는 편이 낫습니다.

## 통계 패널

`통계` 버튼을 누르면 `StatisticsPanel`이 열리고 창이 패널 높이(424px)만큼 늘어납니다. 패널 자체의 높이와 `WindowsOverlayWindow.StatisticsPanelHeight`는 같은 값이어야 하며, 어긋나면 패널 아래가 잘리거나 빈 공간이 생깁니다. `PrefabAssetTests`가 두 값을 함께 고정합니다.

패널 상단에는 탭 두 개(`내 통계`, `랭킹`)와 기간 버튼 세 개(`7일`, `이번 달`, `누적`)가 있습니다. 기간을 바꾸면 서버에 다시 요청하고, 기간에 따라 한 줄이 하루·한 주·한 달이 됩니다. `랭킹` 탭 위쪽의 지표 버튼 네 개(`작업`, `총시간`, `휴식`, `식사`)는 이미 받아 둔 값을 다시 정렬만 하므로 요청이 없습니다.

행 개수는 프리팹에 고정돼 있습니다(내 통계 7행, 랭킹 4행). 행을 늘리려면 `DOTORIONPrefabBuilder`의 배열 크기와 위치 계산, 패널 높이, 그리고 위 두 상수를 함께 고쳐야 합니다.

## 프로필 아이콘

멤버 카드의 아이콘 타일(`TeamMemberCard/Avatar`)을 누르면 `AvatarPickerPanel`이 열리고 창이 패널 높이(160px)만큼 **위로** 늘어납니다. 통계 패널이 아래로 늘어나는 것과 방향만 반대이고, 창 아래쪽 모서리는 제자리에 있습니다. 화면 맨 위에 붙여 둔 경우에는 위로 나갈 자리가 없으므로 작업 영역 위쪽에 붙인 뒤 아래로 늘어납니다.

패널은 `WindowBackground`의 자식이 아니라 형제입니다. 패널이 캔버스 맨 위 160px를 차지하고 `WindowBackground`가 그만큼 아래로 밀리는 구조라, 기존 레이아웃은 서로의 상대 위치를 그대로 유지한 채 통째로 내려갑니다. 패널 높이와 `WindowsOverlayWindow.AvatarPickerPanelHeight`는 같은 값이어야 하며 `PrefabAssetTests`가 둘을 함께 고정합니다.

아이콘 하나를 누르면 그 자리에서 저장됩니다. `확인`은 저장 버튼이 아니라 패널을 닫는 버튼입니다. 통계 패널과 아바타 패널은 동시에 열리지 않습니다. 둘 다 창 크기를 직접 움직이기 때문에 같이 열면 서로 창을 잡아당깁니다.

### 아이콘 추가하기

아이콘이 실제로 그려지는 크기는 **카드에서도 선택창에서도 48x48**입니다. 카드에서는 타일을 여백 없이 꽉 채우고, 선택창에서는 52px 칸 안에 2px씩 들어갑니다. 선택창의 2px은 여백이 아니라 선택된 칸의 색이 테두리로 남게 하는 자리입니다. 아이콘이 칸을 꽉 채우면 어느 것을 골랐는지 표시할 자리가 사라집니다.

**아바타 선택창은 아직 팔레트 색을 칠합니다**(`AvatarPickerPanelView.ApplySelection`). 여기 아트를 넣을 때 같이 정리하면 됩니다. 칸 그래픽을 끄는 방식은 쓰지 마세요 — `Icon`의 Raycast Target이 꺼져 있어서 칸 그래픽이 없으면 그 칸을 누를 수 없습니다.

두 자리를 같은 크기로 맞춰 둔 이유는 픽셀아트 때문입니다. 한쪽만 다른 크기면 그쪽에서만 픽셀이 리샘플링됩니다. 크기는 `DOTORIONPrefabBuilder.AvatarIconSize` 하나에서 나옵니다.

1. `Assets/04. Avatars`에 PNG를 넣습니다.
   - 일반 그림: **128x128 정사각형, 투명 배경**.
   - 픽셀아트: `Assets/04. Avatars/Pixel/` 하위 폴더에 **24x24**(2배) 또는 **16x16**(3배), **48x48**(1:1)도 됩니다. 48의 약수가 아닌 크기는 픽셀 폭이 들쭉날쭉해집니다. 32는 1.5배라 여기에 해당합니다.
2. `DOTORI ON > Refresh Avatar Catalog From Folder`를 누릅니다. `Resources/DOTORION/TeamAvatarCatalog.asset` 목록이 폴더 내용(하위 폴더 포함)으로 갱신됩니다.
3. 목록에 직접 드래그해서 넣어도 됩니다. 카탈로그가 길어지면 선택창 격자가 그만큼 늘어나고, 두 줄을 넘으면 스크롤됩니다.

임포트 설정은 `AvatarSpriteImporter`가 자동으로 걸어 줍니다. 손으로 만질 필요가 없고, 만져도 다음 재임포트에 되돌아갑니다.

| | 일반 그림 | `Pixel/` 하위 |
| --- | --- | --- |
| Filter Mode | Bilinear | **Point** |
| Mip Maps | 켬 | **끔** |
| Texture Type | Sprite (2D and UI) | 같음 |
| Compression | None | 같음 |
| Alpha Is Transparency | 켬 | 같음 |

밉맵을 일반 그림에만 켜는 이유는 축소 배율 때문입니다. 128을 48로 줄이면 밉맵 없이는 가장자리가 반짝거립니다. 반대로 픽셀아트에 밉맵을 켜면 미리 뭉개 둔 사본을 쓰게 되어 픽셀아트인 이유가 사라집니다.

**파일 이름이 곧 서버에 저장되는 키입니다.** 영문·숫자·`.`·`_`·`-`만 64자까지 쓸 수 있습니다. 한글 이름은 `members.avatar_key`의 CHECK 제약이 거부하므로 선택창에서 아예 빠지고, `TeamAvatarCatalogTests`가 빌드 전에 실패로 잡아 줍니다. `default`는 "아이콘 없음"을 뜻하는 예약된 이름이라 쓸 수 없습니다.

파일 이름을 바꾸면 그 아이콘을 고른 사람의 설정이 초기화되어 이름 첫 글자로 돌아갑니다. 서버에는 이름만 저장되고 그림은 클라이언트가 들고 있기 때문에, 나중에 아이콘을 빼도 깨진 이미지가 남지 않고 첫 글자로 되돌아갑니다.

### 기존 프리팹에 붙이기

프리팹을 다시 만들지 않고 `DOTORI ON > Add Avatar Picker To Existing Prefabs`를 한 번 누르면 카드에 버튼과 아이콘 자리가, 메인 화면에 선택 패널이 추가됩니다. 이미 붙어 있으면 아무것도 하지 않으므로 여러 번 눌러도 안전합니다. 수동으로 고쳐 둔 레이아웃은 그대로 남습니다.

아이콘 크기를 바꿨을 때는 `DOTORI ON > Apply Avatar Icon Layout`을 누릅니다. `AvatarIconSize`와 카드 줄 위치를 이미 있는 프리팹에 다시 써넣습니다. 위 명령과 나눠 둔 이유는 이쪽은 해당 rect를 덮어쓰기 때문입니다. 카드의 이름·상태·상세 줄 위치를 손으로 조정해 뒀다면 이 명령이 되돌립니다.
