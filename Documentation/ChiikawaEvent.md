# 치이카와 토벌 대작전

현재 적용 그림은 사용자 승인 v4 시트이며 `Documentation/ChiikawaApprovedArt.md`를 따른다. 기존 24도트 평균 축소 시도는 폐기했다.

`DOTORIONApp._enableChiikawaEvent`가 유일한 장착 지점이다. 끄면 버튼·투명 창·상점·전투·동기화를 생성하지 않는다. 기존 출퇴근 RPC와 팀 상태 조회는 이벤트 테이블에 의존하지 않는다.

이벤트 기간은 **2026/10/19 11:10 ~ 2026/11/30 23:59(서울)**다. 이 기간 문구는 관리창 `보상` 탭 상단에 표시한다. `SubjugationEvent.StartsAt` 전에는 앱이 이벤트를 붙이지 않으므로 빌드를 먼저 배포해도 보이지 않는다. 앱이 켜진 채로 시작 시각이 지나면 1초 안에 버튼·스트립과 함께 나타난다. 판정은 PC 시계 기준이다. `SubjugationEvent.EndsAt`(12월 1일 00:00 KST)이 지나면 앱은 실행 시 이벤트를 장착하지 않고, 실행 중이면 스스로 제거된다(스트립·버튼·관리창·프로필 라운드 표시·창 높이가 원래대로 돌아간다). 별도 업데이트는 필요 없다. 서버 `chiikawa_event_ends_at()`도 같은 시각부터 보상 수령을 거절한다. 받은 포인트와 개인 저장 파일은 남는다.

- 기본 치이카와 1명, 코인 0, 라운드 1.
- 치이카와 → 하치와레 → 우사기 → 모몽가 → 시사 → 랏코 순서로 고용한다. 보유는 6명, 동시 출전은 1~3명이며 대기 멤버와 교체할 수 있다.
- 출근 상태 + 작업중 + 연결 정상 + 최근 하트비트에서만 전투한다. 상태 변경 요청 처리 중에는 진행을 보류한다. 휴식·식사·퇴근 중에는 피해·보상·재도전 타이머 모두 정지한다. 오프라인 경과 시간은 보상하지 않는다.
- 라운드마다 적 1마리, 처치 시 코인을 받고 자동 진행 ON이면 다음 라운드, OFF이면 현재 라운드를 반복한다. 패배하면 실패 표시(3초) 뒤 한 라운드 아래로 내려가 반복 ON 상태로 싸운다(예: R7 패배 → R6 반복). R1에서 지면 R1을 다시 한다. 최고 라운드는 그대로다. 매 전투가 시작될 때 전투 위에 `ROUND n` 표시가 1.2초 뜬다(보스는 빨간 판). 전투는 멈추지 않으며, 작업 중이 아닐 때는 표시 시간도 멈춘다. 전투 HP는 다음 실행 때 초기화하고 라운드·코인·레벨·출전 명단은 보존한다.
- 전체호출 왼쪽의 사스마타 아이콘은 표시 설정이다. 숨겨도 작업중이면 전투는 계속된다. 설정은 재실행 후 유지된다.
- 적은 출전 멤버별 체력 중 가장 앞 생존자 1명만 공격한다. 쓰러진 멤버는 전용 도트로 교체하고 전멸하면 한 라운드 아래에서 반복한다. 시사는 살아 있는 출전 멤버 전원(자신 포함)을 회복한다.
- 최대 라운드는 100, 최대 레벨은 100이다. R100 클리어 후에는 R100을 반복한다.
- 10의 배수 라운드는 보스(체력 ×2.5, 공격 ×1.4, 보상 ×2.5)다. 보스 라운드는 `R.` 표시와 적 체력바가 빨간색이다.
- 반복 버튼이 ON이면 현재 라운드를 반복하고 OFF이면 승리 후 다음 라운드로 이동한다.
- 개발자 대시보드 Ctrl+Shift+D에서 이벤트 코인 +9999를 지급할 수 있다. `이벤트 초기화`는 4초 안에 두 번 누르면 이 계정의 로컬 진행(백업 포함)을 지우고, 서버의 이벤트 라운드와 보상 포인트를 지운다. 관리자는 팀 전체, 그 외에는 본인 것만 지운다. 다른 팀원 PC에 남은 진행은 그 팀원의 다음 동기화 때 다시 올라온다. 출석 포인트는 건드리지 않는다.
- 재화 영역을 누르면 관리창이 열린다. 관리창은 `대원`·`보상`·`라운드` 세 탭이며 마지막으로 본 탭으로 열린다. 스트립의 `R.` 표시를 누르면 `라운드` 탭으로 바로 열리고, 그 탭이 열려 있으면 닫힌다. `라운드` 탭은 현재/최고 라운드, 도달한 라운드로 이동, 현재 라운드 반복 ON/OFF를 담는다(이동하면 창이 닫힌다). `대원` 탭은 보유 멤버의 출전/대기·코인 레벨업, 다음 멤버 고용, 이후 잠긴 멤버를 표시한다. 다른 설정/통계 창이나 소형 모드와 동시에 열지 않는다.
- `보상` 탭은 R10·R20…R100 클리어 보상 버튼 10개다. 해당 라운드를 실제로 이긴 뒤(`bestClear`) 누르면 라운드 숫자만큼 도토리온 포인트(R10 10P … R100 100P, 합계 550P)를 한 번 받는다. 받을 수 있는 보상이 있으면 탭에 개수를 표시한다. 포인트는 출석 포인트와 같은 누적값에 더해지고, 받은 직후 출석 포인트 표시를 다시 읽는다.

## 조정할 데이터

`Assets/Resources/DOTORION/Events/ChiikawaBalance.json`의 고용 비용·시작 레벨·레벨업 비용·보상·능력치는 15일(90시간) 안에 R100을 겨우 클리어하도록 맞췄다. 공식과 시뮬레이션 결과는 `Documentation/ChiikawaBalance.md`에 기록한다.

현재 캐릭터는 `Art/ChiikawaCharacters-v3.png`를 바탕으로 24도트 전투 마스터(화면에서는 2배인 최대 48px)와 32px 얼굴 도트를 사용한다. 우사기의 네 가지 모습은 공식 입 모양을 반영한 `Art/UsagiCanonicalMouth-v3.png`를 사용한다. 제한 팔레트와 Point 확대를 적용하고, 투명 가장자리에는 검은 번짐이 생기지 않도록 알파를 고려해 축소한 뒤 도트를 만든다. 100/150/200%에서도 동일한 도트 원형을 유지한다. 고용 창에서는 얼굴·이름·레벨·최대체력·공격력(시사는 회복량)·버튼·출전 인원을 표시하며 캐릭터별 설명과 하단 설명은 제거했다. 이전 그림은 보존한다. 현재 프롬프트와 참고 자료는 `Documentation/ChiikawaPixelV3.md`, 이전 작업은 `Documentation/ChiikawaArt.md`에 기록한다.

## 창과 저장

Windows 일반 모드에서는 메인 Unity Canvas 위에 토벌 스트립 480×64를 포함한다. 상단 64px 공간을 추가하고 magenta 색상 키를 투명 처리한다. 독립 이벤트 창을 만들지 않아 메인 창 드래그와 정확히 함께 움직인다. 소형 모드에서만 별도 알파 창을 생성하여 독립적으로 드래그한다. 관리창 또는 라운드 선택을 열면 일반 모드로 복귀한다. Editor에서는 투명 Canvas로 미리보기한다.

전투 해상도와 동일 배율 규격은 `Documentation/ChiikawaPixelGrid.md`에 기록한다. 현재 개별 체력·반복 토글·통합 창·소형 모드·적 10종·디버그 지급의 상세 사항은 `Documentation/ChiikawaFrontline.md`에 기록한다. `ChiikawaCombat.md`는 이전 전투 구조 기록이다.

개인 진행은 `Application.persistentDataPath/Events/chiikawa-v1-<member-id>.json`에 저장한다. 계정별로 분리하고 임시 파일→교체 및 이전 `.bak`를 유지한다. 구매 직후·10초 간격·일시 정지·종료 때 저장한다. 손상된 본문은 백업을 읽으며 둘 다 읽을 수 없으면 원본을 보존하고 진행을 중단한다. 현재 개인 경제는 로컬 저장이며 기기 간 공유나 서버 권위 검증을 제공하지 않는다.

## 팀 라운드

`supabase/migrations/202610180001_chiikawa_event_rounds.sql`을 서버에 적용해야 팀원 라운드를 공유한다. 클라이언트는 30초마다 자신의 현재 라운드(`round`, 낮은 라운드를 고르면 내려감)와 최고 도달 라운드(`max_round`, 올라가기만 함)를 게시하고 같은 팀의 값을 조회한다. RLS는 같은 팀만 읽게 하며 RPC는 인증된 활성 멤버 본인의 라운드만 갱신한다. 표시용 라운드만 공유하고 코인/고용은 업로드하지 않는다. 서버에 마이그레이션이 없어도 개인 게임과 기존 출퇴근은 동작하고 동기화 대기 안내를 한 번 표시한다.

프로필에는 모든 팀원의 라운드를 `R현재(최고)` 형식으로 기존 출근 타이머 위 독립 라벨에 표시한다. 글꼴·크기·색 등은 기존 타이머 설정을 따른다. 개인 표시 끄기로 라운드 표시도 숨긴다.

## 보상 포인트 (서버)

적용 순서: `202610180001_chiikawa_event_rounds.sql` → `202610190001_point_awards.sql` → `202610190002_chiikawa_event_rewards.sql`. 2026-10-18에 원격 프로젝트에 적용했고, 출석 상태·랭킹·이벤트 함수가 실제 멤버 권한으로 정상 동작하며 기존 누적 포인트가 그대로임을 읽기 전용 쿼리로 확인했다.

- `202610190001_point_awards.sql`은 이벤트와 무관한 공통 변경이다. 출석이 아닌 포인트를 담는 `member_point_awards` 원장(member, source, award_key 기본키로 중복 지급 불가)과 누적 계산 함수 `member_total_points`를 만들고, 누적 포인트를 돌려주는 기존 함수 4개(`claim_daily_check_in`, `daily_check_in_status`, `team_activity_ranking`, `admin_member_overview`)가 이 함수를 쓰도록 바꾼다. 그 외 본문은 그대로다.
- `202610190002_chiikawa_event_rewards.sql`은 `claim_chiikawa_event_reward(p_milestone, p_cleared)`와 `chiikawa_event_claimed_rewards()`를 만든다. 서버는 마감 시각, 마일스톤(10~100, 10 단위), 금액(= 라운드), 1회 지급을 강제한다. 클리어 여부는 클라이언트 로컬 진행을 그대로 믿으므로(서버가 전투를 검증하지 않음) 조작 시 최대 550P까지 받을 수 있다.
- 마이그레이션이 없거나 모의 백엔드면 보상 탭은 안내 문구만 보이고 버튼은 비활성이다. 게임과 출석은 그대로 동작한다.

## 모듈 경계

이벤트 코드는 `Assets/01. Scripts/08. Events/`, 리소스는 `Assets/Resources/DOTORION/Events/`, 테스트는 별도 asmdef `Assets/Tests/`에 있다. 기존 코드가 이벤트를 아는 곳은 아래뿐이며, 모두 이벤트가 없을 때 기본값(0, 숨김)으로 동작한다.

- `DOTORIONApp`: 장착/해제 블록 한 곳과 `_enableChiikawaEvent` 플래그.
- `DOTORIONView`·`TeamMemberCardView`·`WindowsOverlayWindow`: 스트립 높이·관리창 높이·프로필 라운드 라벨 확장 지점. `SubjugationEvent.OnDestroy`가 모두 0/숨김으로 되돌린다.
- `SupabaseTeamBackend`는 `partial`이며 이벤트 RPC는 이벤트 폴더의 `SupabaseSubjugationRounds.cs`에 있다.
- 개발자 대시보드의 코인 지급 버튼은 이벤트가 붙였다가 제거한다.
- 이벤트 전용 에디터 도구 `SubjugationArtImporter.cs`, `SubjugationPreview.cs`는 `Assets/90. Editor/`에 있다.

## 검증

EditMode `DOTORION.Tests.SubjugationTests`: 초기 상태, 비작업 중지, 처치 보상, 패배 시 한 라운드 후퇴·반복 ON, 라운드 시작 표시, 고용 순서, 출전 제한, 구매 조건, 과도한 경과시간 방지, HP 회복 악용 방지, 계정별 저장과 백업 복구, 시작 레벨·최대 레벨/라운드, 보스, R100 관문, 마일스톤 클리어 판정, 이벤트 마감 시각을 확인한다.

`DOTORION.Editor.SubjugationPreview.Export`는 실제 계정 없이 상태별 픽셀 스트립과 관리창 시안을 `Logs/ChiikawaPreview`에 출력한다.
